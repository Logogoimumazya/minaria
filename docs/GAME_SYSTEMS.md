# ระบบเกมที่ผูกกับเมือง และแผนทำเป็น mod

เอกสารนี้บอกว่าอาคารใน `CITY_PLAN.md` ทำงานกับระบบเกมอย่างไร และส่วนไหนควรย้ายจากสคริปต์ Python ไปเป็น mod
มีสามชั้น: สิ่งที่ใช้ได้ทันทีจาก mod ที่มีอยู่ → สิ่งที่ทำด้วย KubeJS → สิ่งที่ต้องเขียนเป็น mod Forge

## 1. ของที่มีอยู่แล้วในแพ็ก (ตรวจจาก jar และสคริปต์แล้ว)

| ระบบ | อยู่ที่ไหน | ใช้กับอาคาร |
|---|---|---|
| ชื่อเสียงกับ 5 ฝ่ายของ bible (นักล่า, ศาสนจักร, หอจดหมายเหตุ, เอลฟ์, ลัทธิ) | `kubejs/server_scripts/minaria_factions.js` (−100..100 ต่อผู้เล่น) | กิลด์นักผจญภัย, โบสถ์, โรงงานหอจดหมายเหตุ |
| อาณาเขตและขุนนางท้องถิ่น (`/realm`, `/standing`) | `confluence_world.js` | เรือนขุนนาง, โรงทหาร |
| งานล่าบนบอร์ด | Bountiful (`bountyboard`) + `kubejs/data/bountiful` (มี pool และ decree อยู่แล้ว) | กิลด์นักผจญภัย |
| ชาวบ้านมีชีวิต ชื่อเสียง อาชญากรรม | MCA, MCA Reputation, MCA Crime | ทุกบ้าน, ศาลากลาง และคุก |

| หีบของรางวัลแยกต่อผู้เล่น | Lootr | ห้องนิรภัยของธนาคาร, คลังโรงทหาร |
| เวทมนตร์ | Iron's Spellbooks (`inscription_table`, `scroll_forge`, `arcane_anvil`) | สมาคมจอมเวท |

ลำดับงานของระบบทั้งหมดอยู่ใน [`GAMEPLAY.md`](GAMEPLAY.md) ข้อ 8

## 2. ระบบที่ทำด้วย KubeJS (ไม่ต้องคอมไพล์)

1. **บอร์ดงานประจำแคว้น:** Bountiful เลือก pool ตามไบโอม ส่วนเราอยากให้เลือกตามแคว้น
   - บอร์ดในเมืองวาลาเรียให้งานทหารชายแดน บอร์ดของศาสนจักรให้งานล่าเอลฟ์
   - ใช้ decree ต่อแคว้น แล้วให้บอร์ดที่วางตอนสร้างเมืองมี decree ของแคว้นนั้นติดมา
   - ต้องตรวจว่า Bountiful 6.0.4 เก็บ decree ในบอร์ดอย่างไร ก่อนเขียน NBT ลงบล็อก
2. **ชื่อเสียงจากงานกิลด์:** ส่งงานล่าที่บอร์ดของสมาคมนักล่า → ชื่อเสียงกับนักล่า +2 ใช้ event ส่งงานของ Bountiful ถ้ามี
   ถ้าไม่มี ให้ใช้ FTB Quests
3. **ภาษีผ่านประตูเมือง:** เข้านครของแคว้นที่ผู้เล่นมีชื่อเสียงต่ำ ทหารที่ประตูเรียกค่าผ่าน
   - ใช้พื้นที่ประตูจาก `D:/Minaria/world/qa/<town>/build.npz` แปลงเป็น JSON ใส่ kubejs/data
4. **ธนาคาร:** ตู้เซฟ Supplementaries ล็อกของได้อยู่แล้ว ส่วนดอกเบี้ยหรือเงินกู้ต้องมีสกุลเงิน
   ตรวจก่อนว่าในแพ็กมีระบบเงินอะไร (บางตัวเช่น Bountiful ใช้มรกต)

## 3. แผนทำเป็น mod Forge: `minaria_world`

ตอนนี้เมืองถูกสร้างด้วย Python ลงไฟล์ region ก่อนเล่น วิธีนี้ได้คุณภาพสูง แต่ทำได้เฉพาะในทวีป 16,384 บล็อก
พื้นที่นอกทวีป (ดินแดนสะท้อน) เป็น chunk ที่เกมสร้างเอง ยังไม่มีเมืองของเรา

**เป้าหมายของ mod**
1. **เมืองนอกทวีป:** ส่งคลังชิ้นส่วน (KL, civic, ชนบท) เป็น structure ของเกม ให้เมืองในดินแดนสะท้อนใช้ของชุดเดียวกัน
   jigsaw ธรรมดาทำพื้นต่างระดับได้ไม่ดี จึงใช้ structure type ของเราเอง ที่อ่านความสูงพื้นก่อนแล้วจัดวางแบบ town.py
   Lithostitched มีในแพ็กแล้ว ช่วยเรื่องแก้ไข structure ได้
2. **ป้ายบอกทางที่นับระยะจริง:** บล็อกป้ายที่อ่าน settlements.json แล้วแสดงชื่อเมืองกับระยะจากตำแหน่งผู้เล่น
3. **สมุดทะเบียนกิลด์:** บล็อกในกิลด์นักผจญภัยที่เก็บอันดับนักล่าของเซิร์ฟเวอร์ (มี leaderboards อยู่แล้ว ดูว่าต่อได้ไหม)
4. **ข้อมูลอาณาเขตในเกม:** อ่าน `settlements.json` กับข้อมูลรัฐ ใช้แทนการเดาพิกัดใน `confluence_world.js`
   ตรงกับ WORLD_PLAN W7

**ลำดับทำ:**
1. ข้อ 4 ก่อน เพราะเล็กและใช้ทันที
2. ข้อ 2
3. ข้อ 1 ใหญ่ที่สุด ทำหลังจากเมืองในทวีปนิ่งแล้ว
ใช้โครง gradle เดียวกับ `dev/minaria_court` (Forge 1.20.1 build แบบ offline ได้)

## 4. เงินและภาษี (ตัดสินแล้ว 2026-09-25)

### เงิน: เหรียญแบบ Terraria จาก Confluence
มีใน jar แล้ว: `confluence:copper_coin`, `silver_coin`, `gold_coin`, `platinum_coin` รวมถึง `piggy_bank`
(เก็บเงินข้ามที่ได้) และ `mechanic_safe_chest`

**ผู้เล่นรู้แค่สามอย่าง:**
1. เหรียญ 100 อันแลกเป็นเหรียญขั้นถัดไป (ทองแดง → เงิน → ทอง → แพลทินัม) แบบเดียวกับ Terraria
2. ฆ่าศัตรู ทำงานล่า และขายของ ได้เหรียญ
3. ซื้อของ จ่ายภาษี และฝากธนาคาร ใช้เหรียญ

**เบื้องหลัง:**
- ราคาอ้างอิงต่อเทียร์ขององก์ (bible หัวข้อ 9) ขององก์ 0 ราคาเป็นทองแดงถึงเงิน องก์ II ขึ้นไปเป็นทอง
- บอร์ดงานของ Bountiful จ่ายเป็นเหรียญ Confluence แทนมรกต (แก้ใน `kubejs/data/bountiful`)
- **กฎ:** ต้องตรวจก่อนว่า Bountiful ตั้งรางวัลเป็นไอเทมใดก็ได้ไหม

### ชื่อกลาง (ใช้ไปก่อน เปลี่ยนภายหลังได้ที่เดียวใน `kubejs/data/minaria/names.json`)
- **สภาพ่อค้า:** "สภาพ่อค้าแห่ง<ชื่อแคว้น>" (Merchants' Council of <state>)
- **ธนาคาร:** "เรือนเงินออรัม" (Aurum Counting House) ทุกสาขา
- **กิลด์นักผจญภัย:** "สมาคมนักล่า สาขา<ชื่อเมือง>" (Hunters' Lodge, <town> chapter)
- **ภาษี:** "ค่าผ่านประตู" (gate toll) และ "ภาษีตลาด" (market tax)

### ภาษีจริง แต่เข้าใจง่าย

**ค่าผ่านประตู**
- เข้านครหรือเมืองที่มีกำแพงผ่านประตู ยามเรียกเก็บ 1 ครั้งต่อวันเกม
- อัตรา: นคร 5 เหรียญเงิน · เมือง 1 เหรียญเงิน · หมู่บ้านไม่เก็บ
- **ส่วนลดตามชื่อเสียง** กับขุนนางท้องถิ่น (`/standing`): สูงกว่า 50 ฟรี, ติดลบจ่ายสองเท่า
- **จ่ายไม่ไหวหรือไม่จ่าย:** เข้าได้ แต่ค่าหัวของ MCA Crime ขึ้น ยามจำหน้าได้
- **สิ่งที่ผู้เล่นเห็น:** ข้อความเดียวบนหน้าจอ "ค่าผ่านประตู Aileau: 5 เงิน (จ่ายแล้ว)"
- เขตประตูอ่านจาก `build.npz` ของแต่ละเมือง (ตอนนี้บันทึกถนนออกประตูกับปลายถนนไว้แล้ว)

**ภาษีตลาด**
- ขายของให้พ่อค้าในเมือง ถูกหักภาษีตามแคว้น:
  - ออรัม 5% (การค้าเสรี)
  - วาลาเรีย 10%
  - ออสทรัม 20% (ภาษีสงคราม)
  - แดนเสรี 0% แต่ราคาซื้อสูง
- ราคาที่แสดงเป็นราคาหลังหักภาษีแล้ว ผู้เล่นไม่ต้องคิดเลข

**เงินภาษีไปไหน**
- เข้าคลังของแคว้น (ตัวเลขใน saved data) คลังเต็มแล้วแคว้นนั้นส่งทหารลาดตระเวนมากขึ้น และซ่อมกำแพงเร็วขึ้น
- ผู้เล่นเห็นแค่ผลลัพธ์ในเมือง ไม่ต้องจัดการเอง
- ต่อยอดได้ในอนาคต: ขุนนางที่ผู้เล่นช่วย (minaria_court) ลดภาษีให้

**ธนาคาร (เรือนเงินออรัม)**
- ฝากเหรียญได้ และถอนได้ทุกสาขา (บัญชีผูกกับผู้เล่น ใน saved data)
- ไม่มีดอกเบี้ยในองก์แรก เปิดดอกเบี้ย 1% ต่อสัปดาห์เกมเมื่อชื่อเสียงกับออรัมสูง
- ตู้เซฟ Supplementaries ในธนาคารเป็นบริการเช่าตู้เก็บของ
- **สิ่งที่ผู้เล่นทำ:** คลิกเสมียน (ชาวบ้าน MCA ในธนาคาร) → เมนู ฝาก / ถอน / ยอด

**เครื่องมือ**
- ค่าผ่านประตูกับภาษีตลาดทำด้วย KubeJS ได้ทั้งหมด (event ผู้เล่นเข้าเขต, event การค้า)
- บัญชีธนาคารข้ามสาขาต้องมี saved data ใช้ `persistentData` ของผู้เล่นได้ใน KubeJS
- ไม่ต้องใช้ mod ใหม่ในขั้นแรก
